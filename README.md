# Бот университетского расписания

Python 3.13, aiogram 3, APScheduler. Сервер работает в Render Free через Telegram webhook.
Автоматическая утренняя рассылка в облачной версии выключена.

## Несколько учебных групп

1. Пользователь отправляет `/start` и номер группы.
2. Если группа уже подключена, расписание доступно сразу.
3. Если подключения нет, бот выдаёт личную ссылку на HTTPS-форму на 15 минут.
4. Студент вводит данные кабинета вуза и подтверждает использование аккаунта для расписания группы.
5. Бот проверяет вход, определяет доступные группы из кабинета и проверяет загрузку занятий.
6. Проверенное подключение сохраняется в Neon. Другие участники видят только расписание.

Кнопки: «На сегодня», «На завтра», «На неделю», «Моя группа».
Команда `/group` меняет выбранную группу. Номер группы можно также отправить сообщением.
Владелец подключённого аккаунта может отозвать его командой `/disconnect`.
Никогда не отправляйте пароли обычными сообщениями боту.

## Восстановление

Когда вуз отклоняет вход или аккаунт теряет доступ к группе, под сообщением появляется
«Сбросить аккаунт группы». Нажать её может любой пользователь, выбравший эту группу.
Перед сбросом бот повторно проверяет вход и загрузку расписания. Если всё снова работает,
подключение сохраняется. Если аккаунт по-прежнему не работает, данные входа удаляются,
после чего любой участник может подключить свой аккаунт той же группы.

Пустой день, сетевой сбой и изменение формата сайта не разрешают сброс аккаунта.
Кнопки от прежнего подключения не могут удалить новое. Зашифрованные данные не удаляются
автоматически при ошибке ключа шифрования: сначала нужно восстановить правильный ключ.

## Хранение и нагрузка

В Neon хранятся Telegram ID, выбранные группы, зашифрованные данные входа и хеши
временных ссылок. Логин и пароль шифруются Fernet; отдельный `CREDENTIALS_KEY` хранится
в переменных окружения Render. Не меняйте его произвольно: без прежнего ключа
сохранённые подключения нельзя расшифровать.

Ввод логина и пароля проходит только через HTTPS-форму на сервере бота.
Страница не подключает сторонних скриптов, шрифтов и аналитики. Значения пароля
не возвращаются в HTML и не записываются в журналы приложения.
Разрешено не более пяти попыток входа в час для одного Telegram ID.

Расписание загружается за неделю и сохраняется в памяти на 10 минут для каждой группы.
Одновременные запросы одной группы объединяются; к вузу выполняются не более двух
операций одновременно. При каждом новом подключении используется отдельный сеанс вуза.
Проверка `/health` не обращается к базе и не расходует её квоту запросами мониторинга.

## Настройки Render

Команда сборки: `pip install -r requirements.txt`.
Команда запуска: `python -u cloud.py`.
Проверка состояния: `/health`.

Для режима нескольких групп нужны:

- `BOT_TOKEN` — токен Telegram-бота.
- `WEBHOOK_SECRET` — случайный секрет от 32 до 256 символов: буквы, цифры, `_`, `-`.
- `DATABASE_URL` — строка подключения к Neon PostgreSQL.
- `CREDENTIALS_KEY` — постоянный ключ Fernet.

Render автоматически задаёт `RENDER_EXTERNAL_URL`. При другом размещении нужен
`WEBHOOK_BASE_URL` с HTTPS-адресом сервера без пути.

Если `DATABASE_URL` и `CREDENTIALS_KEY` не заданы, сохраняется прежний режим одной группы
1241 с `UNIVERSITY_USERNAME` и `UNIVERSITY_PASSWORD`. Наличие только одной из двух новых
переменных считается ошибкой настройки. Старые данные кабинета не переносятся в Neon
автоматически: первую группу подключают через форму после переключения режима.

Локальный `.env.neon` содержит закрытые настройки базы для разработки. Он исключён из Git.
Не загружайте `.env`, `.env.neon`, содержимое `data/` или ключи в репозиторий.
Не запускайте локальное получение обновлений Telegram, пока работает серверный webhook.

## Проверки

Обычные проверки используют вымышленные данные и тестовый Telegram-сеанс:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Проверки SQL и общего подключения запускаются отдельно при наличии `.env.neon`:

```sh
RUN_NEON_TESTS=1 .venv/bin/python -m unittest discover -s tests -v
```

Для них нужна пустая база проекта с таблицами из `schema.sql`.
Изменения тестовых данных откатываются транзакцией. Реальный аккаунт вуза не используется.

## Бесплатные тарифы

Render Free засыпает после простоя и может отвечать с задержкой при пробуждении.
У Neon Free есть месячные квоты вычислений, хранения и трафика. Это не гарантия
непрерывной работы. Платёжная карта для выбранного тарифа Neon не требуется.
